# Jepsen on GCP: all six VMs e2-standard-2, 12 vCPU

Date: 2026-11-17. Status: accepted (owner decision, binding). Supersedes the
22 vCPU sizing in decision 7 of `2026-11-17-gcp-opentofu.md`; that file is
not edited.

## Context

The first live run (Actions run 44171731137, `gcp.yml` on `main`) failed at
`tofu apply`:

    Quota 'CPUS_ALL_REGIONS' exceeded. Limit: 12.0 globally

The project's global CPU quota, `CPUS_ALL_REGIONS`, is 12. The owner has
decided it will not be raised. The decision doc of the same day assumed the
regional quota (24 in us-central1) was the binding one: it is not. The global
cap applies on top of the regional one, so a 22 vCPU cluster cannot fit
regardless of region.

A run is five nodes plus one control VM, six VMs in all, so every VM has to
be `e2-standard-2` (2 vCPU each, 12 in total).

## Decisions

1. **All six VMs are `e2-standard-2`** (2 vCPU, 8 GiB each): five nodes
   `n1`..`n5` and the control VM. `tofu/variables.tf` sets
   `node_machine_type` to `e2-standard-2`; the control machine type was
   already `e2-standard-2`. Nothing else in the cluster changes.
2. **Cost.** On-demand us-central1, about $0.07 per VM-hour, so the six VMs
   are about $0.42 an hour, and about $0.50 an hour with the disks and the
   NAT gateway. A run of 40 to 60 minutes is roughly $0.35 to $0.50.
3. **Consequence for the tests.** Jepsen nodes now have 8 GiB instead of
   16 GiB and 2 vCPU instead of 4, so a run may be slower. If the time budget
   in `gcp/check-inputs.sh` or the job timeouts in `gcp.yml` proves too tight
   for the default tests, raise it then, in a PR of its own, with a live run
   as the evidence.

## Rejected

- **Raising `CPUS_ALL_REGIONS`.** The owner has ruled it out.
- **Keeping the 22 vCPU sizing and raising the regional quota.** It does not
  help: the global cap of 12 still applies.
- **Mixing sizes**, for example bigger nodes. Any node with more than 2 vCPU
  puts five nodes plus the control VM over 12 (3 x 5 + 2 = 17).

## Not done / open

- Not yet run live with the new sizes. The next dispatch on `main` is the
  test.
- **No vCPU headroom.** 12 of 12 vCPU means any VM already in the project fails the next run's `tofu apply` with the quota error. That includes a cluster left by a failed destroy (until the sweeper removes it after 4 h), a hand-made VM, or a control VM still deleting. Fix by hand or wait for the sweeper; a preflight quota check in `gcp.yml` is a possible follow-up.
- The 40 to 60 minute duration and the cost range are estimates, unmeasured on 2 vCPU / 8 GiB nodes.
